# 책을 선택 모듈로 분리하고 해외 서지를 연결한다

책 기능은 사용자가 선택한 **내장 선택 모듈**로 분리하고, 제품의 기본 역할은 범용 hledger 프런트엔드로 유지하는 것이 적합하다. 탭을 숨기는 것만으로는 서버 권한과 자동 조회가 분리되지 않는다. 원장별 활성 상태를 서버가 관리하고 웹·모바일·API가 같은 정책을 적용해야 한다. 해외 서지는 SeoJi 성공을 전제로 하지 않는 별도 공급자 경계가 필요하며, 키 없이 사용할 기본 후보로 Open Library를 권고한다. 이 문서는 코드와 공식 문서 조사에 따른 **설계 제안**이다. 외부 API 실호출, 국가별 검색 성공률 측정, 구현은 수행하지 않았다.

## 원장별 서버 설정이 책 기능의 경계를 만든다

현재 웹은 책 화면을 항상 마운트한 뒤 숨기며 목록을 조회한다. 모바일도 화면을 유지하지만 조회에는 활성 화면 조건이 있다. 서버의 책 resolver에는 기능 활성 여부를 검사하는 경계가 없다. 따라서 웹·모바일 화면과 서버 도메인을 내장 모듈로 구분하고, 코어가 capability와 진입점을 제공하도록 제안한다. 초기 registry는 내장 모듈 ID·버전, API resolver 등록과 웹·모바일 진입점만 관리한다. 중앙 SDL·operations·codegen은 공유 계약으로 유지하며 모듈별 SDL 조립이나 패키지 제외는 도입하지 않는다. 모듈은 앱 shell 내부를 import하지 않고 API·복구·i18n의 코어 context를 전달받는다. 코어의 영속 설정은 endpoint나 기기 설정 대신 **canonical ledger ID**를 키로 사용한다. 클라이언트가 직접 GraphQL을 호출해도 동일한 제한을 적용한다. ([웹 화면](/Users/moreal/github/moreal/hledger-app/apps/web/src/App.tsx), [모바일 화면](/Users/moreal/github/moreal/hledger-app/apps/mobile/LedgerApp.tsx), [서버 resolver](/Users/moreal/github/moreal/hledger-app/services/api/schema.ts))

배포 시 책 패키지를 제외하는 구성은 빌드 조합이 늘어나므로 후속 후보로 둔다. 제3자 코드를 설치하는 런타임 플러그인은 사용자가 선택한 이번 범위에서 제외한다. GraphQL SDL은 활성 여부에 따라 제거하지 않고 고정한 채 capability와 명시적인 비활성 오류를 추가한다. 웹과 Expo가 공유하는 생성 계약을 유지하고, 비활성 상태를 ‘책이 0권’인 응답으로 표현하지 않는다. ([공유 계약](/Users/moreal/github/moreal/hledger-app/packages/api-contract/schema.graphql), [계약 생성 안내](/Users/moreal/github/moreal/hledger-app/docs/graphql-codegen.md))

## 비활성화 후에도 원장과 미확정 요청은 보존한다

책은 원장의 거래·태그·단위·원가에서 재구성된다. 끄기는 삭제가 아니므로 일반 거래·계좌·가격 조회와 기존 `book.*`, `asset:book:` 자료를 유지해야 한다. 일반 쓰기가 예약된 책 메타데이터를 위조하지 못하도록 하는 보호도 코어에 남긴다. 전문 책 조회·신규 쓰기·서지와 표지 외부 요청은 비활성 상태에서 차단한다. 클라이언트의 원격 표지 이미지도 내리고 모듈 소유 fetch를 가능한 범위에서 취소하되 이미 전송한 요청을 되돌릴 수는 없다. 캐시된 서지는 보존하고 자동 갱신하지 않는다. 외부 공급자에는 정규화 ISBN과 해당 공급자의 키·앱 식별자만 전달하며 원장·계좌·hledger 인증 정보를 보내지 않는다. ([책 기록 구현](/Users/moreal/github/moreal/hledger-app/services/api/books.ts), [예약 데이터 보호](/Users/moreal/github/moreal/hledger-app/services/api/schema.ts))

웹과 모바일의 미확정 요청은 책 화면보다 먼저 코어에서 복구하도록 옮긴다. 원래 원장 식별자·입력·멱등키·초안·선택 언어를 보존하며 다른 키로 자동 재생성하지 않는다. 초기 구현은 **알려진 미확정 요청을 해결하기 전 끄기를 막는 단순한 정책**을 권고한다. 다른 기기의 미전송 요청까지 서버가 알 수는 없으므로, 나중에 발견된 요청은 비활성 상태에서 입증 가능한 결과만 읽기 전용으로 확인한다. 결과가 불명확하면 계속 미확정으로 표시하고 명시적으로 다시 켠 뒤 같은 키로 복구한다. 임의의 키를 ‘재시도’라고 부르는 것만으로 비활성 쓰기를 허용하면 안 된다. 복잡한 admission/receipt 저장소는 비활성 상태에서 쓰기 재개가 꼭 필요한 후속 요구가 생길 때 검토한다. ([웹 요청 보존](/Users/moreal/github/moreal/hledger-app/apps/web/src/Books.tsx), [모바일 요청 보존](/Users/moreal/github/moreal/hledger-app/apps/mobile/Books.tsx))

새 원장은 기본 off를 제안한다. 기존 실제 책 기록이나 미확정 요청이 발견된 원장은 일회성 마이그레이션으로 사용을 유지하고 안내한다. 계좌 이름만으로 사용 여부를 판정하지 않으며, 서버가 알 수 없는 로컬 요청은 연결 시 보존·안내한다. 이 기본값과 마이그레이션 정책은 아직 구현되지 않은 제안이다.

## Open Library로 SeoJi 없는 해외 조회를 시작한다

현재 SeoJi는 404나 실패에서 즉시 반환하고 성공한 뒤에만 표지 폴백을 실행한다. 따라서 기존 표지 폴백은 해외 서지 폴백을 의미하지 않는다. 책 기록은 수동 제목·저자로 외부 조회 없이 가능해야 하며, **서지 공급자와 표지 공급자를 독립시켜야 한다**. ([현재 조회 경로](/Users/moreal/github/moreal/hledger-app/services/api/seoji.ts))

Open Library Books API는 키 없는 공개 조회 예시와 제목·저자·식별자·표지를 제공한다. ISBN은 작품 묶음인 Work 대신 Edition을 기준으로 확인한다. 기본 제한은 미식별 요청 초당 1회, 앱 이름·연락처로 식별하면 초당 3회이며 대량 수집용 서비스가 아니다. 개인 앱의 사용자 요청 조회와 캐시를 결합하는 구성이 적합하다. Open Library를 기본 해외 공급자로, SeoJi를 선택적 보완 공급자로 두는 정책을 제안한다. UI 언어만으로 ISBN의 국가나 책 언어를 추정하지 않는다. ([Books API](https://openlibrary.org/dev/docs/api/books), [API 이용 지침](https://openlibrary.org/developers/api))

유효한 ISBN-10과 ISBN-13의 체크섬을 확인하고 대응 가능한 두 형식을 정규화하여 정확히 같은 판본인지 비교한다. 검색 첫 결과나 Work 대표 표지를 채택하지 않는다. 확인된 Edition의 CoverID를 우선하며, 표지 누락은 `default=false`의 404로 구분한다. 정확한 ISBN 일치는 후보 레코드 선택 기준이며 원천 오류나 동일 ISBN의 다른 쇄 때문에 실물 판본·표지가 맞는다는 보장은 아니다. 사용자는 출처를 확인하고 요청 키를 바꾸지 않은 채 제목·표지를 교체하거나 표지를 제거할 수 있어야 한다. 메타데이터 개방이 모든 표지의 저작권 소멸을 뜻하지 않으므로 출처와 사용 조건을 보존하고 캐시·삭제 규칙을 공급자별로 관리한다. ([Covers API](https://openlibrary.org/dev/docs/api/covers), [권리 안내](https://openlibrary.org/developers/licensing))

## Google과 지역별 기관은 실제 미검색 사례에 맞춰 추가한다

Google Books는 ISBN 검색과 서지·이미지 필드를 제공하지만 공식 경로는 API 키 또는 OAuth 토큰을 요구한다. 따라서 키를 설정한 사용자의 선택 공급자로 둔다. 문서의 라이선스를 응답 데이터와 표지 전체의 라이선스로 해석하지 않는다. ([조회 요구사항](https://developers.google.com/books/docs/v1/using), [Volume 필드](https://developers.google.com/books/docs/v1/reference/volumes), [추가 약관](https://developers.google.com/books/terms))

일본 NDL과 프랑스 BnF는 수요가 확인될 때 추가할 지역별 후보다. NDL은 ISBN 완전 일치 검색을 지원하지만 데이터 제공기관과 이용 목적에 따른 재이용 조건을 검토해야 한다. BnF는 무인증 SRU 조회와 출처 표시 조건의 서지 재이용을 제공하며 이미지 조건은 별개다. openBD는 현행 API 안내가 존재하지만 대체 서지 전환 뒤 표지 범위가 축소되었고 판촉·소개 목적 조건이 있어 개인 가계부의 기본 공급자로 바로 채택하지 않는다. 이번 조사에서는 각 서비스의 실제 가용성·CORS·국가별 수록률을 측정하지 않았다. ([NDL 사양](https://ndlsearch.ndl.go.jp/help/api/specifications), [NDL 이용 조건](https://ndlsearch.ndl.go.jp/help/api), [BnF SRU](https://api.bnf.fr/fr/api-sru-catalogue-general), [BnF 재이용](https://www.bnf.fr/fr/portail-bnf-api-et-jeux-de-donnees), [openBD](https://openbd.jp/), [전환 공지](https://openbd.jp/news/20230829.html))

다음 승인은 공급자 수보다 원장별 끄기·복구의 정확한 동작과 기본값을 확정하는 데 집중하는 것이 좋다. 그 후 소수의 실제 해외 ISBN으로 판본 일치·누락·장애·표지 출처를 검증하면 지역별 확장의 필요성을 근거로 판단할 수 있다.

초기 registry의 최소 범위, 클라이언트 표지 요청 차단, 공급자 전달 정보 제한과 ISBN 일치의 한계는 설계자가 정리한 제안이며 사용자가 명시적으로 승인한 사항은 아니다.
