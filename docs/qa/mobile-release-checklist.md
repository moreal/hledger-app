# 모바일 CI 산출물 QA 체크리스트

각 실행은 `runs/YYYY-MM-DD-ci-native.md`에 기록한다. iOS와 Android를 별도로 판정하고, 소스 검토·API 응답·빌드 성공만으로 네이티브 UI 항목을 통과시키지 않는다.

상태: `PENDING` 미실행, `PASS` 기대 결과 직접 확인, `FAIL` 기대 결과 불일치, `BLOCKED` 실행 조건 부족, `N/A` fixture/기능상 적용되지 않는 조건부 분기(이유 필수). 각 PASS/FAIL에는 증거 ID와 실제 관찰을 남긴다. 장애가 해결되면 같은 CI 산출물로 재검증한다.

## 실행 준비

- CI 실행 URL, 커밋 SHA, 다운로드 경로, 원본 해시, manifest, 서명/재포장 여부를 기록한다.
- 플랫폼·기기/시뮬레이터·OS·앱 ID·설치 방법·백엔드 주소와 자료 종류를 기록한다. 토큰은 문서·화면 증거에서 가린다.
- 실사용 원장에는 쓰지 않는다. 명시적으로 승인된 별도 격리 원장에서만 W01 저장·판매·폐기·복구를 수행한다. 원장 ID·경로와 격리 여부를 먼저 기록하고, 격리 원장 없이는 W01을 BLOCKED로 남긴다.

## 기능 항목

| ID | 절차와 기대 결과 |
| --- | --- |
| N01 | CI 앱 설치·실행: 시작 화면이 뜨고 충돌/빈 화면이 없다. 항목·거래·입력·시세·책·동기화 및 설정에 접근한다. |
| N02 | 미인증: 연결 안내가 보이고 원장 전송·책 저장이 비활성화된다. 설정에서 주소와 가려진 토큰 입력란을 확인한다. |
| N03 | 연결 적용: 유효한 테스트 연결은 원장 식별자·인증 상태를 표시한다. 잘못된 주소/토큰은 오류를 표시하고 인증된 것처럼 보이지 않는다. |
| N04 | 설정 복귀·재실행: 주소는 기억되고 인증 토큰은 앱 종료 후 사라진다. 새 인증 확인이 필요하다. |

| N06 | 거래: 검색·기간·항목·자산·태그 필터, 빈 결과, 상세의 분개/태그/참고 번호를 확인한다. 페이지가 있으면 더 보기를 확인한다. |
| N07 | 입력: 최근 거래 복사 후 내용·날짜·분개·태그를 확인한다. 내역/태그 추가·삭제, 일반/주식 매매 전환, 자산 선택, 빈 새 거래를 확인한다. 실사용 원장에는 저장하지 않는다. |
| N08 | 입력 검증: 잘못된 날짜·빈 항목·부적절한 금액/불균형을 입력하고 저장 전 검증 안내를 확인한다. 유효한 요청은 전송하지 않는다. |
| N09 | 시세: 자산/기준 자산·기간으로 조회하고 결과 또는 빈 결과 안내를 확인한다. |
| N10 | 동기화: 대기 수·빈 목록 또는 보관 요청 상태가 표시된다. 인증/다른 연결의 재시도 제한을 확인한다. 실사용 원장의 기존 요청은 전송·삭제하지 않는다. |
| B01 | 책: 목록 새로고침 후 제목·ISBN·보유 상태·장부 가치 또는 빈 목록이 보인다. 기존 자료가 있으면 표지/없음 표시도 확인한다. |
| B02 | ISBN `9788936434595`: 자동 조회 완료 후 제목·저자·표지 이미지와 출처를 실제 화면에서 확인한다. URL/API 값만으로 표지 통과 처리하지 않는다. |
| B03 | ISBN `9780000000002`: 미검색/조회 실패 안내 후 제목·저자를 수동 입력할 수 있다. 구매 금액·통화·항목 입력란도 사용할 수 있다. 실사용 원장에는 저장하지 않는다. |
| B04 | 수동 입력 보존: 수동 제목·저자를 적고 ISBN 정보 다시 조회를 누른다. 응답 후에도 수동 값이 유지된다. ISBN 변경 시 이전 표지·출처가 남지 않는다. |
| B05 | 책 검증: 잘못된 ISBN·날짜·빈 제목·0/음수 구매 금액의 검증 안내를 확인한다. 저장 요청을 보내지 않는 입력만 사용한다. |
| U01 | 네이티브 사용성: 스크롤로 하단 버튼에 접근하고 키보드 표시/해제 후 입력·탭 전환이 가능하다. 글자·금액·표지가 잘리거나 겹치지 않는다. |
| W01 | 격리 원장 전용 확장: 거래/책 구매·판매·폐기 저장, 오프라인 보관·재시도·요청 키 중복 방지와 재실행 복구를 검증한다. 격리 원장 미제공 시 BLOCKED. |

## 증거와 완료 판정

스크린샷/화면 녹화·런타임 로그는 절대 경로로 연결하고, 어떤 ID·플랫폼·시점의 증거인지 명시한다. API 보조 증거는 네이티브 관찰과 구분한다. 실패는 재현 단계·기대/실제·영향·후속 조치를 기록한다. 필수 항목에 PENDING/FAIL/BLOCKED가 있으면 전체 통과로 보고하지 않는다.
