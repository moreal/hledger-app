# 선택형 책 모듈과 국제 ISBN 조회 설계

상태: **PROPOSED** · 작성일: 2026-10-25

사용자가 승인한 방향은 **내장 선택 모듈 우선, 제3자 런타임 설치 제외**다. 아래 활성 정책·계약·마이그레이션·공급자 우선순위는 승인 검토용 제안이며 구현 완료를 뜻하지 않는다. 근거는 [조사 보고서](</Users/moreal/github/moreal/hledger-app/reports/선택형 책 기능과 해외 서지.md>)와 코드 조사다. 외부 API를 직접 호출하거나 커버리지를 측정하지 않았다.

## 목표와 범위

범용 hledger 프런트엔드가 기본 제품으로 동작하고 책은 원장별로 켜는 기능이 된다. 웹·모바일·API가 같은 활성 정책을 따르며 비활성 상태의 불필요한 화면 적재·자동 조회·외부 서지 호출을 없앤다. 기존 원장 자료와 미확정 쓰기 복구를 보존한다. SeoJi 없이도 해외 ISBN 조회와 수동 구입 기록이 가능해야 한다.

제3자 코드 설치, 런타임 샌드박스, 플러그인 마켓, 모든 국가 공급자 동시 연동, 대량 서지 수집, LLM 기반 서지 추론은 범위 밖이다. 이 문서는 구현 순서별 상세 작업 계획이 아니라 승인할 동작과 경계를 정의한다.

## 검토한 접근

| 접근 | 판단 |
|---|---|
| 책 탭만 숨기기 | 서버 직접 호출·자동 조회·복구 결합이 남아 목표에 부족 |
| 내장 선택 모듈 | 사용자 선택. 단일 저장소와 공유 계약을 유지하면서 웹·모바일·API 경계 분리 |
| 빌드 시 별도 패키지 포함 | 필요 시 후속 검토. 배포 조합과 복구 호환성 비용 증가 |
| 외부 런타임 플러그인 | 이번 범위 제외. 권한·격리·버전·공급망을 별도 설계해야 함 |

## 코어와 모듈 경계

초기 registry는 first-party 모듈 ID·버전, API resolver 등록과 웹·모바일 진입점만 가진다. 현재 중앙 SDL·operations·codegen을 공유 계약으로 유지하고 모듈별 SDL 빌드 조립이나 패키지 제외는 도입하지 않는다. 모듈은 앱 shell 내부를 import하지 않으며 API·복구·i18n의 코어 context를 전달받는다. 이 최소 범위는 설계자 판단에 따른 제안이다.

코어는 연결·인증·원장 정체성·일반 거래/계좌/가격 읽기·예약 데이터 보호·설정·capability·요청 복구를 소유한다. books 모듈은 책 상태 재구성·구입/처분·전문 조회·웹/모바일 화면·서지/표지 공급자 등록을 소유한다. 현재 `books.ts`가 `seoji.ts`를 경유해 가져오는 표지 정규화 같은 공통 도메인 규칙은 특정 공급자에 의존하지 않도록 한다.

웹은 capability 확인 후 활성 모듈의 진입점만 구성하고 필요한 시점에 화면을 적재한다. 모바일도 활성 모듈만 마운트하되 웹 lazy import와 같은 번들 제거 효과를 전제하지 않는다. API resolver는 UI와 독립적으로 모든 책 전문 query/mutation 및 외부 조회를 검사한다. 외부 조회는 사용자 요청에 따라 수행하고 비활성 원장에서는 예약 작업·캐시 갱신을 포함해 책 외부 네트워크 요청을 시작하지 않는다. 클라이언트의 새 원격 표지 이미지 요청도 금지한다. 끌 때 책 이미지를 unmount하고 모듈 소유 fetch를 가능한 범위에서 취소한다. 이미 전송한 요청은 되돌릴 수 없다. 캐시된 서지는 유지하되 자동 갱신하지 않는다.

비활성 상태에서도 기존 거래·태그·가격·원가·관리 단위를 삭제하거나 변환하지 않는다. 일반 조회는 책 상태 재구성 성공에 종속되지 않는다. `book.*`, `asset:book:` 예약 메타데이터를 일반 입력으로 위조하지 못하도록 기존 쓰기 보호를 항상 유지한다.

## 서버가 원장별 활성 상태를 결정한다

서버의 영속 설정을 canonical ledger ID로 식별한다. 최소 저장 항목은 books enabled, 설정 버전, 마이그레이션 버전이다. endpoint·localStorage·기기의 탭 표시 취향은 권위가 아니다. 여러 클라이언트가 같은 원장에 연결하면 같은 상태를 보고, 설정 변경은 서버에서 권한을 확인하고 버전 충돌을 처리한다. 구체적인 저장 형식과 기존 인증 모델에서 설정 변경을 허용할 주체는 구현 전 확정한다.

새 원장은 기본 off를 제안한다. 업그레이드 시 실제 관리 책 기록이나 서버가 확인한 미확정 작업이 있는 기존 원장은 사용 유지 결정을 한 번 기록하고 안내한다. `assets:books` 계좌 이름만으로 활성화하지 않는다. 손상된 관리 태그를 자동 복구하지 않는다. 서버가 볼 수 없는 기기 pending은 코어가 연결 시 발견하여 보존하고, 비활성 상태라면 복구 안내를 제공한다. 로컬 증거만으로 공유 설정을 조용히 켜지 않는다.

## 끄기와 미확정 요청 복구

초기에는 단순한 enabled/disabled 정책을 제안한다. 끄기를 요청한 클라이언트에 알려진 pending이 있으면 먼저 해결하도록 막는다. 서버는 설정 변경과 신규 책 쓰기 admission을 직렬화하여, 이미 시작한 작업의 결과를 정리하기 전 비활성 전환이 완료된 것으로 알리지 않는다. 서버가 다른 기기의 미전송 pending을 모두 알아야 한다는 전제는 두지 않는다.

웹의 기존 `hledger.book-request:${client.identity}`와 모바일의 `books-pending-v1` 복구를 책 화면 밖 코어로 끌어올린다. 기존 형식 읽기와 이전을 지원하며 원래 입력·멱등키·원장/연결 식별자·초안·선택 언어를 유지한다. 토큰은 pending 자료에 넣지 않는다. 켜기/끄기·탭 이동·언어 변경·재연결이 기존 요청을 덮어쓰거나 다른 키로 재생성해서는 안 된다.

비활성 상태에서 복구 UI는 남는다. 서버가 기존 영속 멱등 기록으로 입증할 수 있는 결과만 읽기 전용으로 반환한다. 기존 저장 구조가 결과를 입증하지 못하면 ‘미확정’을 유지한다. 기록 없음은 미수행의 증명이 아니다. 원래 원장에 연결하고 사용자가 명시적으로 다시 켠 뒤 같은 입력·키로 기존 복구 경로를 사용한다. **임의의 키를 재시도라고 주장해 비활성 상태에서 쓰기를 실행할 수 없다.** 조회인 척 기존 mutation을 실행하는 경로도 허용하지 않는다.

비활성 상태의 쓰기 재개가 필수라는 후속 요구가 생기기 전에는 별도 receipt/admission 기반 draining 시스템을 추가하지 않는다. 그 요구가 생기면 원장·작업·키·fingerprint·승인 시점의 영속 검증과 crash recovery를 별도 설계해야 한다.

## GraphQL과 공유 클라이언트 계약

SDL의 책 타입과 필드는 on/off에 따라 제거하지 않는다. 고정 계약에 인증된 capability를 추가해 지원 버전·현재 원장 상태·허용 동작(전문 조회, 신규 쓰기, 서지, 읽기 전용 복구)을 알린다. 비활성 책 작업은 명시적인 `FEATURE_DISABLED` 의미를 반환하며 빈 목록으로 위장하지 않는다. 실제 필드 이름·오류 전달 형식은 기존 nullable·오류 처리와 함께 검토한다.

웹과 Expo는 같은 typed operations와 생성 결과를 사용한다. 계약 변경 시 schema validation·codegen·양쪽 typecheck와 활성/비활성/복구 통합 검증이 필요하다. 오래된 클라이언트의 직접 호출도 서버 gate를 통과할 수 없다.

## 서지와 표지를 독립 공급자로 조회한다

수동 제목·저자 입력은 공급자 설정이나 조회 성공 없이 동작한다. 외부 공급자에 전달하는 입력은 정규화 ISBN과 공급자별 키·앱 식별자로 제한한다. 원장·계좌·hledger 인증 정보는 전달하지 않는다. metadata provider와 cover provider는 별도 인터페이스·설정·상태·timeout·캐시 정책을 가진다. SeoJi 성공 후에만 다른 공급자를 호출하는 현재 경로를 제거한다. Open Library를 키 없는 기본 해외 서지 후보, SeoJi를 선택적 보완 후보, Google Books를 키 설정 시 선택 후보로 제안한다. NDL/BnF는 실제 미검색 사례에 따른 후속 후보다.

입력 ISBN은 하이픈·공백 제거와 체크섬 검증 뒤 canonical ISBN-13으로 비교한다. 유효한 ISBN-10은 대응하는 978 ISBN-13으로 변환하고, 979 ISBN에 존재하지 않는 ISBN-10을 만들지 않는다. 공급자 식별자도 같은 방식으로 정규화해 정확한 판본 일치를 확인한다. Work나 제목 유사성만으로 판본을 확정하지 않으며 Work 대표 표지로 대체하지 않는다. 정확한 ISBN 일치는 후보 레코드 매칭 기준이다. 원천 데이터 오류나 같은 ISBN의 다른 쇄가 있으므로 실제 소장 판본·표지의 정확성을 보장하지 않는다. UI 언어는 책 언어·출판 국가·판본을 결정하지 않으며 한국어 UI에서 해외 ISBN도 그대로 조회한다.

필드 또는 선택 레코드에 공급자·원본 식별자·출처 URL·조회 시각을 남기고 서지와 표지의 출처를 별도로 기록한다. 수동 수정 값은 자동 응답으로 덮어쓰지 않는다. 사용자가 제목·표지를 교체하거나 표지를 제거할 수 있으며 이 편집으로 기존 미확정 요청의 키·보존 입력을 변경하지 않는다. 미검색·장애·표지 없음은 구분하고 실패해도 수동 기록으로 진행한다. 응답 파싱과 선택은 결정적인 규칙으로 수행하며 LLM을 사용하지 않는다.

캐시는 정규화 ISBN·공급자·관련 옵션을 키로 하며 성공/미검색을 구분한다. 보존 기간·갱신·삭제는 공급자별 약관에 맞춰 정하고 모든 공급자에 같은 무기한 캐시를 적용하지 않는다. Open Library rate limit과 앱 식별 지침을 준수한다. 표지는 확인된 Edition의 식별자를 우선하며 권리·안전 URL 정책을 적용한다. 제3자 페이지나 이미지 파일을 앱에 묶어 배포하지 않는다. 외부 URL을 사용하는 것만으로 표지 권리 검토가 끝났다고 가정하지 않는다.

공식 근거: [Open Library Books](https://openlibrary.org/dev/docs/api/books), [API 지침](https://openlibrary.org/developers/api), [표지](https://openlibrary.org/dev/docs/api/covers), [권리](https://openlibrary.org/developers/licensing), [Google Books](https://developers.google.com/books/docs/v1/using), [NDL](https://ndlsearch.ndl.go.jp/help/api), [BnF](https://api.bnf.fr/fr/api-sru-catalogue-general). 문서 기반 후보 선정이며 실제 가용성·커버리지는 검증하지 않았다.

## 단계별 범위와 수용 기준

**1단계 — 선택 모듈 경계와 복구:** 서버 설정·capability·웹/모바일 진입·코어 복구·마이그레이션. 새 off 원장에서 책 화면과 자동 조회가 없고 직접 API 호출도 차단된다. 기존 기록의 일반 조회와 예약 보호가 유지된다. 알려진 pending이 있으면 끄기가 막히고 다른 기기에서 뒤늦게 발견된 pending은 보존된다. 비활성 복구는 외부 호출이나 쓰기 없이 입증 가능한 결과만 확인한다. 언어·초안·원래 키가 활성 상태 변경을 거쳐 유지된다.

**2단계 — 공급자 분리와 해외 기본 조회:** SeoJi 독립화·Open Library 서지/표지·수동 입력·출처·캐시. SeoJi 미설정/404/장애에서도 해외 ISBN 조회가 가능하다. ISBN-10/13 동등성·979·오판본·표지 누락·timeout을 검증한다. 한국어 UI에서 해외 책이 조회되고 수동 수정 값이 유지된다. 계약 생성과 양쪽 클라이언트 검증이 통과한다. 실제 표본 조회는 이 단계에서 별도로 수행하고 결과와 한계를 기록한다.

**3단계 — 선택 공급자 확장:** 수요와 약관 검토 후 Google 키 설정, NDL/BnF를 추가한다. 공급자별 가용성·할당량·재이용 조건·실제 미검색 개선을 확인한 뒤 기본 정책 변경을 판단한다.

## 승인된 선택과 남은 결정

사용자 결정: 내장 선택 모듈을 먼저 도입하며 제3자 런타임 설치는 하지 않는다.

설계자 판단으로 정리했으며 아직 사용자 명시 승인을 받지 않은 세부 선택: 최소 registry와 중앙 공유 계약 유지, shell 내부 import 금지와 코어 context 전달, 클라이언트 이미지 요청 차단, 공급자 입력 제한, ISBN 일치의 한계와 사용자 교체 경로.

승인 대상 제안: 서버 원장별 권위, 새 원장 off와 기존 사용 유지 마이그레이션, pending 해결 전 끄기 제한, 불명확한 복구의 명시적 재활성화, 고정 GraphQL 계약, Open Library 기본 해외 공급자, Google/지역 공급자의 선택적 후속 도입.

구현 전 결정: 설정의 실제 저장 위치·변경 권한·동시성 방식, 영속 기록으로 읽기 전용 결과를 확인할 수 있는 범위, 로컬 pending 이전 세부 규칙, 공급자별 캐시 기간·오류 모델·표지 취급. 이 문서 승인 후 파일 소유권과 상세 구현 계획을 작성한다.
