# ISBN 기반 실물 도서 자산

ISBN은 판본을 식별한다. 같은 ISBN을 여러 권 보유할 수 있으므로 구매 요청마다 별도 복본 ID와 `asset:book:<20자리 ID>`를 생성한다. ISBN-10/13 체크 숫자를 검증하고 ISBN-10은 ISBN-13으로 정규화한다. Books를 활성화한 원장에서 ISBN을 입력하면 Open Library를 먼저 조회하고, 명시적으로 설정한 경우 SeoJi를 보완 공급자로 사용한다. 조회 실패·미등록·표지 누락 시 직접 입력으로 계속 진행할 수 있다.

## 원장별 활성화와 복구

Books는 원장별로 켜는 내장 선택 모듈이다. 새 원장은 기본 off이며, 최초 설정 시 읽기 전용 검사로 확인한 기존 관리 책 기록이 있으면 사용 유지를 위해 한 번 on으로 초기화한다. 계좌 이름만으로 활성화하지 않는다. 서버는 실제 원장 경로와 연결된 `<실제 원장 경로>.features.json`에 활성 상태·설정 버전·마이그레이션 버전을 저장한다. 설정이나 기존 기록을 검증하지 못하면 임의로 초기화하지 않고 오류를 반환한다.

`ledgerFeatures`가 현재 원장의 권한을 알려 주며 `setBooksEnabled`는 기존 bearer 인증과 `expectedVersion`으로 설정을 변경한다. 다른 클라이언트가 설정을 바꾸면 최신 버전을 다시 읽어야 한다. 끄기는 기존 거래·태그·가격·관리 단위를 삭제하거나 변환하지 않는다. 일반 원장 조회와 예약 메타데이터 보호는 유지되며 책 목록·구매·처분·서지 조회는 `FEATURE_DISABLED`로 차단된다. 비활성 클라이언트는 새 책 서지·원격 표지 요청을 시작하지 않는다. 이미 전송한 요청은 되돌릴 수 없다.

끄기를 요청한 클라이언트에 알려진 확인 대기 요청이 있으면 먼저 해결해야 한다. 다른 기기에서 뒤늦게 발견된 요청도 원래 입력·키·원장 식별자와 함께 보존한다. 비활성 상태의 `bookRequestStatus`는 원장을 변경하지 않는 검사로 원래 요청 전체와 영속 증거가 일치할 때만 `CONFIRMED`를 반환한다. 증거 부족·읽기 전용 검사 불가·중단된 쓰기는 `UNKNOWN`으로 남으며 기록 없음만으로 미수행을 판단하지 않는다. 원래 원장에 연결해 명시적으로 Books를 다시 켠 뒤 동일 입력·키로 복구한다.

## 원장 기록

- 구매: 책 1권에 구입금액을 `@` 가격으로 기록하고 결제 계좌에서 같은 금액을 차감한다. 구입금액은 양수이며 장부가액으로 유지한다.
- 판매: 책 1권을 구입 장부가액으로 차감한다. 현금은 판매금액에서 수수료를 뺀 금액만큼 증가한다. 판매금액과 구입금액 차이는 이익/손실 항목, 수수료는 별도 비용 항목에 기록한다. 화면의 실현손익은 수수료까지 반영한다.
- 폐기: 책 1권의 장부가액을 차감하고 같은 금액을 폐기손실 항목에 기록한다. 대금은 발생하지 않는다.

예: 10,000원에 산 책을 12,000원에 팔고 수수료 500원을 내면 현금 +11,500원, 책 자산 -10,000원, 처분이익 2,000원, 수수료비용 500원으로 기록하며 순손익은 +1,500원이다. 7,000원에 팔면 수수료 반영 손익은 -3,500원이다. 폐기하면 손실 10,000원이다.

판매 결제 자산은 구입 자산과 같아야 한다. 자동 환산·감가상각·세금 신고·증여·무료 취득·책 분할은 지원하지 않는다. 이 계정 처리는 개인 원장 관리 모델이며 법정 회계나 세무 처리를 대신하지 않는다.

## 상태와 중복 방지

`books`, `purchaseBook`, `disposeBook` GraphQL API가 인증된 원장에 연결된다. 도서 목록은 실제 원장에 저장한 관리용 태그와 가격에서 재구성하므로 별도 목록 데이터베이스가 필요 없다. 제목은 안전한 인코딩으로 기록한다.

구매는 요청 키에서 복본 ID를 만들며 같은 요청 재실행은 한 권만 만든다. 같은 ISBN을 다른 요청으로 구매하면 별도 책이다. 처분은 한 복본에 한 개의 영속 요청 키를 사용해 서로 다른 프로세스에서 동시에 요청해도 하나만 성공한다. 날짜·가격·요청을 바꾼 재시도는 충돌한다. 판매/폐기 이후 구매 요청을 다시 확인해도 현재 상태를 반환한다.

클라이언트는 네트워크 전송 전에 정확한 요청과 키를 로컬에 저장한다. 응답이 불명확하면 입력을 잠그고 동일 요청으로만 재시도한다. 저장소 손상이나 기록 실패 시 새 요청을 차단한다. 현재 원장과 다른 원장의 요청을 섞지 않는다.

관리용 `book.*` 태그와 `asset:book:` 원장 단위는 일반 거래 API에서 직접 생성하지 못하도록 예약한다. 원장 파일을 외부에서 직접 수정하여 관리 정보가 일치하지 않으면 오류로 알리고 상태를 추정하지 않는다. 기존 원장 거래는 자동 이전하거나 변경하지 않는다.

## 사용

웹·모바일의 ‘책’ 화면에서 ISBN, 제목, 구매일, 구매금액, 결제 자산과 계좌를 입력한다. 보유 중인 책을 선택하면 판매 또는 폐기를 기록할 수 있다. 판매된 책과 폐기된 책도 이력에 남는다. 모바일 도서 작업은 연결된 API가 필요하며, 일반 거래 전송함과 분리된 확인 대기 요청으로 보관한다.

## 검증 결과 (2026-10-23)

전체 테스트 218개, 전체 TypeScript 검사, 웹 프로덕션 빌드, iOS·Android Expo 번들 내보내기 통과. 실제 hledger 임시 원장과 HTTP/생성 클라이언트를 통해 구매·판매·폐기, 순손익, 재시작·동일 요청 재시도, 동시 처분, 잘못된 ISBN 및 위조된 관리 정보를 검증했다. 실제 웹의 책 탭과 입력 화면을 확인했다. 모바일 실기기 조작은 이번 검증에 포함하지 않았다. 실제 사용자 원장은 변경하지 않았다.

주요 변경: `packages/domain/src/books.ts`, `services/api/books.ts`와 각 테스트; GraphQL 계약·공유 작업·클라이언트; 웹/모바일 `Books.tsx` 및 탭 연결. 앞선 주식 매매 문서는 `docs/stock-trades.md`에 정리했다.

## 서지와 표지 자동 조회

원장 API 서버는 키 없는 Open Library Books API를 먼저 조회한다. SeoJi 미설정·404·장애와 독립적으로 동작한다. Open Library에서 일치하는 서지를 얻지 못했을 때만, 서버 환경에 `HLEDGER_SEOJI_URL`을 명시한 경우 해당 서비스의 `/api/v1/books/{ISBN13}`을 조회한다. 기본 localhost 보완 호출은 없다. 클라이언트가 임의 공급자 URL을 전달할 수 없으며 모바일도 원장 서버를 통해 조회한다.

Open Library 응답은 정규화 ISBN과 식별자가 일치하는 Edition(`/books/OL…M`)만 후보로 받는다. ISBN-10은 대응하는 978 ISBN-13과 비교하며 979 ISBN도 그대로 검증한다. Work·제목 유사성·다른 ISBN만 있는 응답은 사용하지 않는다. 출처는 선택된 Edition URL과 Open Library attribution으로 표시한다. 이 일치는 후보 선택 기준이며 원천 오류나 같은 ISBN의 다른 쇄 때문에 실제 소장 판본·표지 정확성을 보장하지 않는다.

Open Library 서지는 기본 4초·1MiB 한도로 조회하며 리디렉션을 거부한다. 프로세스 전체의 새 네트워크 요청 간격은 최소 1초이고 동일 ISBN 동시 요청은 합친다. 메모리 캐시는 최대 500개로 성공 1일, 미검색 5분, 장애 5초다. `HLEDGER_OPEN_LIBRARY_USER_AGENT`로 앱 식별자를 설정하며 기본값은 `hledger-app/0.1`이다. 서지 요청에는 정규화 ISBN과 앱 식별자만 보내며 원장·계좌·API bearer token을 전달하지 않는다.

표지는 일치한 Edition 응답의 검증된 cover ID를 우선하고 없으면 정확한 ISBN Covers 주소를 조회한다. 표지 조회는 서지와 별도이며 실패해도 제목·저자를 유지한다. 기본 3.5초·2MiB 한도, 허용된 HTTPS 표지/Archive 리디렉션 최대 2회, JPEG 디코딩·크기 검사를 적용한다. 캐시 키는 ISBN과 cover ID이며 성공 1일·실패 5분, 최대 500개다. 프로세스당 5분에 새 조회 40개를 허용한다. 브라우저 원본 이미지 요청은 별도이며 여러 API 프로세스가 같은 IP를 공유하면 합산 제한을 운영 환경에서 적용해야 한다.

선택적 SeoJi 경로도 ISBN을 요청 전 정규화하고, 응답 ISBN이 일치해야 한다. 서지 요청에 4초·1MiB 한도 및 리디렉션 거부를 적용한다. 미등록은 NOT_FOUND, 서비스 장애·잘못된 응답은 UNAVAILABLE로 반환하며 구매 입력은 계속 허용한다. 제목 200자·저자 20명 제한을 넘으면 잘라 저장하지 않고 수동 입력을 안내한다.

입력을 잠시 멈추면 자동 조회한다. ISBN을 바꾸면 이전 자동 정보·표지를 지우고 오래된 응답을 무시한다. 사용자가 직접 고친 제목·저자를 늦은 응답으로 덮어쓰지 않는다. 제목·저자와 표지 URL은 구매 시 함께 저장해 이후 원장 재조회에서도 표시한다. 기존 책 기록은 저자 없음·표지 없음으로 정상 호환한다.

SeoJi 보완 경로의 표지는 HTTPS 국립중앙도서관 주소를 우선 사용하며, 누락되면 ISBN 일치 Open Library Covers와 YES24 공개 상품 페이지를 제한적으로 조회하고, YES24 표지가 없으면 알라딘 공개 상품 페이지를 순차 조회한다. YES24는 검색 후 상품의 ISBN과 같은 Book 객체의 표지를 검증하며 다른 ISBN의 표지를 대신 사용하지 않는다. 알라딘도 상품의 books:isbn·og:barcode와 Book/단일 workExample ISBN이 모두 일치해야 하며 JPEG 실체를 디코딩해 확인한다. 검증용 응답 바이트는 메모리에서 검사하고 페이지·이미지 파일을 저장소나 앱 배포물에 포함하지 않는다. 화면은 원본 URL을 연결하며 URL 연결만으로 표지 재이용 권리 검토가 끝나는 것은 아니다. 주소 누락·이미지 로딩 실패는 대체 표시로 처리한다. 출처는 응답의 공식 LOD 링크 또는 실제 조회한 seoji API 주소로 표시한다.

이전 검증 기록(2026-10-24): 로컬 서비스의 ISBN 9788936434267은 아몬드·손원평·표지 없음, 9780000000002는 NOT_FOUND를 반환했다. 표지 제공·잘못된 표지·장애·타임아웃은 통제된 응답 테스트로 검증했다. 실제 표지가 없는 자료를 표지 성공 사례로 주장하지 않는다. 전체 테스트 226개, 타입 검사, 웹 빌드와 iOS/Android 번들 내보내기가 통과했다. 실제 원장 구매 기록은 추가하지 않았다.

공개 표지 대체 소스의 조사 결과·제한·실측은 [book-cover-sources.md](book-cover-sources.md)를 참고한다.
