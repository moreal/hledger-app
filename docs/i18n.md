# Korean and English UI

Lingui 6.10.1 provides shared Korean (`ko`) and English (`en`) catalogs. Korean is the default. Both catalogs are bundled, so language switching does not need the network. The explicit preference is local to each app/device; it is independent of connection credentials, drafts and the outbox.

## Current scope

Navigation, screen headings, connection settings/guidance, common transport errors and domain transaction, stock, book purchase/disposal/lookup and asset-search forms are translated on web and native. The web document title and language attribute also update. The shared catalogs contain 756 messages per language (excluding the PO header). Ledger records, user-entered book metadata, asset catalog data, arbitrary server diagnostics and the gallery body retain their original content; this is an incremental localization.

Account paths, asset symbols/IDs, ISBNs, exact decimal strings, wire dates and idempotency keys are never translated or converted. Language changes do not remount the ledger app. Native trade inputs are controlled by the ledger screen, and transaction, entry, books and price views stay mounted while hidden so visiting language settings preserves their drafts and visible validation state. Runtime tokens still disappear on restart. Interrupted-write messages retain the warning that the result may be unknown and must be checked with the same request.

## Durable outbox messages

Saved snapshots retain `version: 1`. New records may add validated optional `messageInfo` semantic metadata alongside the original `message`; old records without it remain readable. Rendering uses the current locale without rewriting stored messages, request inputs, endpoints or idempotency keys. Unknown/raw server diagnostics remain verbatim. A rejected retry after an uncertain write still warns that the earlier outcome is unknown. Changing language never sends or retries a request.

Legacy rendering recognizes only exact app-owned literals for interruption, rejection, unconfirmed/unknown saves, endpoint mismatch, timeout/network failure, invalid JSON/GraphQL/save confirmation, and the anchored HTTP status form `The ledger returned HTTP NNN.` (100–599). The exact suffix ` The earlier write outcome is still unknown.` localizes the uncertainty warning while preserving an unrecognized diagnostic prefix. No broad substring translation or storage migration is used.

## Adding messages

Use literal descriptors with stable semantic IDs and a Korean default. The annotation lets the CLI extract messages without adding Babel/SWC macro transformation to Rollipop or Vite.

```tsx
const { _ } = useLingui();
return <h2>{_(/* i18n */ { id: 'settings.language', message: '언어' })}</h2>;
```

Import React bindings from `packages/i18n/src/react` and locale/runtime helpers from `packages/i18n/src/index`. Call `useLingui()` in components that render translations so they subscribe to locale updates. Translate errors during rendering rather than storing an already-translated sentence in state. Preserve server-provided diagnostic strings and request IDs.

Use ICU placeholders/plurals instead of joining translated sentence fragments for new messages. Distinct Korean wording needs a distinct ID even when two platforms have similar controls.

```sh
yarn i18n:extract
# Complete packages/i18n/locales/en/messages.po and review ko/messages.po.
yarn i18n:compile
yarn i18n:check
yarn test:i18n
```

Commit both PO source catalogs and generated TypeScript catalogs. `i18n:check` regenerates catalogs in a temporary directory and rejects stale PO/TypeScript, missing translations and fuzzy entries without modifying source files. Lingui's `compile --strict` alone can accept missing English using the Korean fallback, so it does not replace this check. Node 22.19+ (within the repository engine ranges) is required.

Native release staging includes `lingui.config.ts` and compiles catalogs before client regression tests and native bundling. CI checks extraction/translation freshness and locale behavior before the release jobs. No experimental runtime macros or new native localization dependency is required.

## Preference behavior

- Web uses `localStorage['hledger.locale']`; unavailable storage does not block switching or ledger operations.
- Native uses a separate `createDurableStorage('locale')` namespace. Late startup hydration cannot override a newer explicit selection, and writes are serialized.
- Missing, malformed or unsupported preferences fall back to Korean. The OS language does not silently change an existing user's app language.
- Settings offers `한국어` and `English`. Stable locale selectors are `locale-ko` and `locale-en`; default Korean labels remain compatible with existing QA. Only selected core controls have stable IDs; the old full QA flows are not yet language-independent.

Existing stories receive the provider but their untranslated content does not become English automatically.
